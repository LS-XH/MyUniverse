# Markdown 内容格式

本文件定义实例正文和 Schema 的对应关系；JSON 文件布局见 [JSON 存储](json-storage.md)，保存与刷新见 [持久化功能](../features/persistence.md)。

重复实例名会阻止解析，错误列出全部冲突名称（同名只列一次），方便在加载、刷新、导入、源码编辑或保存报错时定位。

## Markdown 格式

```markdown
# 人物

## 角色一

### 人物性格

谨慎

### 人物势力

#### 势力名称

[示例势力](势力列表.md#示例势力)
```

一级标题为类名，二级为实例名，三级及更深为成员 Key，正文为 Value；Object 递归子标题，Null 不写正文。类名与 fileName 分开，默认“人物 / 人物列表.md”等是合法映射。

Class 引用为 `[实例](类文件.md#实例)`，包含必要转义。数值与日期以文本写入，Schema 决定类型；没有声明时不能凭数字外观猜 Integer/Decimal。重复成员保持同一 Schema 声明、独立成员身份和出现顺序。

Content 可以包含 Markdown 标题、代码围栏及引用；解析须结合 Schema 与围栏判断，不把长正文内所有标题误当结构。提示文本保存于 Schema.placeholder，不写成用户真实内容。不同层次路径、重复键与引用匹配需保留既有稳定 ID。

### Function 生成成员与来源元数据

函数通过 add 生成的成员使用普通属性标题、正文和子标题；对象编辑器显示“函数名 →”，Markdown 标题旁仅写入 `<!-- 函数名 -->`，解析时从成员键剥离。

```markdown
# 类名

## 实例

### 已声明的可重复属性 <!-- 函数名 -->

普通值
```

内部 `functionOrigin={functionId,name,bindingFieldId}`、成员 ID、Schema ID 和 `functionRuns` 保存在工作区 JSON 中，不导出 `function-sources`、`function-origin` 或执行过程索引。正文标记区分生成成员与用户成员；解析先以声明结构读取正文，再复用匹配的 JSON 身份。缺少 JSON 来源记录时，按函数名和当前实例内的绑定作用域重建来源；来源不唯一时明确报错，不猜测删除对象。函数名的特殊字符使用实体转义，避免破坏注释。

刷新和启动时，实际正文覆盖旧 JSON 中的成员内容和来源标记；旧 JSON 不得补回已从正文移除的成员或阻止外部有效变更。JSON 只辅助确认身份和执行状态。刷新后绑定函数重算仅替换该绑定拥有的生成对象，用户原值和其他绑定结果保留；执行失败保留旧有效结果。保存才把当前对象模型序列化回正文。界面源码及导入保持生成对象只读约束，外部重读以文件为准。

旧 `<!-- <!> 函数名 -->`、function-sources 短索引和 URL 编码 function-origin 仍可读取，保存统一迁移为仅有函数名的注释，不额外触发自动写盘。旧函数结果标题和 function-value 元数据只为兼容解析，不再输出。来源与清理规则见 [Function](../features/functions.md#显示来源和绑定生命周期)。

## 转换与身份保留

model/markdown.ts / markdownParser.ts 提供文档、实例、成员序列化与解析；exportFiles 输出正文、结构、视图和组织配置。传入既有 ClassDocument 与 World，按 Schema 解析、保留身份并校验引用。

实例标签定义 labels 与关联 entityLabels 是 ClassDocument 的样式 JSON，只通过 workspace.json 保存；Markdown 文本与属性 Schema 不增加标签字段。解析正文保留既有样式 JSON，稳定实例 ID 保持染色关联；副本生成新实例/成员 ID 后显式复制同类标签关联，删除实例清理对应关联。

## 结构边界与磁盘正文权威

桌面端仅在加载和显式刷新时读取实际 Markdown；实例名称、成员键和值、重复项的新增和删除均以文件正文为依据。Schema 文件定义允许的结构，不能从正文推断新属性；结构内声明的重复 Class 键，即使没有出现在旧 JSON 快照中，也必须读取。工作区规范化不得按旧版人物模板改写当前 Schema 的 Object 类型。

JSON 保留组织、样式、稳定身份及执行状态，既有成员可用于匹配 ID，但不得约束磁盘正文必须与旧值相同。磁盘解析按正文函数名注释及 JSON 身份记录恢复函数来源，不依据缓存中的来源否决新正文；界面仍禁用生成成员编辑，源码编辑与导入保留只读校验。加载文件解析失败时明确报告文件与错误，不静默回退 JSON 实例内容，且不覆盖文件。

单文件刷新只限制磁盘读取与草稿替换范围，不缩小解析所需的世界类目录。跨类的 Class 键和值继续使用完整世界目录识别，避免刷新人物文件时因缺少关系类型或势力类型而丢弃已声明结构中的成员。

### 未声明内容与固定成员

属性配置是唯一结构来源。读取、导入、编辑 Markdown 不推断新属性、不增加“内容”属性、不把重复标题自动改为可重复，也不根据脚本标题新增函数绑定。未知属性及其子树在对象解析时跳过；未声明函数结果块同样跳过。已声明的 Text/Class 动态键和可重复成员仍按其已有声明解析，已有 Content 内的正文标题仍属于文本内容。未配置时不从 Markdown 反向生成 Schema。

非重复成员的多余同级标题忽略，保留第一个匹配项；已配置固定成员缺失时沿用现有空值恢复规则，不删除配置。模型修改建议额外使用严格未知结构校验并拒绝越界建议。

## 转换入口

[`documentMarkdown`、`entityMarkdown`、`fieldMarkdown`、`exportFiles`](../../src/model/markdown.ts) 负责写出；[`parseDocumentMarkdown`](../../src/model/markdownParser.ts) 负责读取。二者接收已有 Schema 和世界引用目录，保留可匹配身份。正文格式验证见 `tests/markdown.test.ts`；具体执行结果只记录在日志。

已声明 Class 动态键的空项可使用空标题、配置 placeholder/key 或“新属性”；仅在当前层有唯一可用 Class 模板时绑定，保留重复项身份。此规则同样适用于严格提议校验，不增加 Schema，不放宽非重复项及未知标题校验。
