# 聊天界面

本文件负责消息、输入和过程呈现；请求执行见 [聊天功能](../features/chat.md)，存储契约见 [聊天数据](../data/chat.md)。

## 目标选择与输入

无会话时输入区居中，有会话时消息填满主区、输入区在底部。新建、切换和删除会话在创作树下完成，不增加独立会话页面。输入区左下角并排放置 Agent、模型两个下拉框，Agent 在左、模型在右。首次发送后固定 Conversation.target，Agent 选择器只显示创建时的目标且禁用；模型仍可在后续发送前修改。ReAct、高级智能体、多角色扮演分别使用机器人、星光、面具图标；会话树项、选择器和助手头像复用这些图标。Schema 不符合 input 字符串直接调用契约的 Agent 显示禁用原因。

### 光标旁补全

输入 `@` 搜索强制技能与当前世界实例，旧 `/` 技能补全继续兼容，菜单跟随实际光标，支持中文邻接、上下键选择、Enter/Tab 确认、Escape 关闭；输入法组合输入不发送。选择后显示引用标签：世界实例复用类徽标、实例名和标签色，技能使用书本图标与名称；内部保留稳定身份。输入区改为 contenteditable，引用是 contenteditable=false 的原子标签模块；点击有固定像素反馈，右键可删除，键盘亦可删除；序列化仍输出原 token 和稳定身份。用户消息同样显示标签，复制保留可移植文字。不可用技能显示原因；删除引用文字即不再应用。菜单沿用当前主题并避让窗口边缘。

角色会话的“我在场景中”紧随模型选择器右侧，窄宽度允许换行。

### 模型能力配置

Agent 配置页以纵向能力列表显示工具、子 Agent 和高级 Agent 的 Skill 许可；展示名称、说明、选中数量和停用状态。普通实例可解除或清理失效接入，特化系统实例仅显示只读能力。子 Agent 可使用自定义 Schema，由模型生成参数，不受聊天直接选择 Agent 的 input 契约限制。模型菜单只显示模型，Agent 菜单只显示 Agent；模型选择只供图中“系统默认模型”选项使用，首次发送创建会话。

### 阅读位置与发送状态

阅读位置距消息底部超过 64px 时，在输入区上方居中显示圆形下箭头按钮，点击回到最新消息；滚动回底部自动隐藏，减少动画偏好时直接定位。离开底部时新流式内容不抢走阅读位置。右下角只保留一个发送/停止按钮：空闲时发送，运行时原位切换为停止，取消仍保持可点击。

## 消息、过程与提议

请求由 AppRoot 管理，切页仍写回原世界/会话；失败/取消保留已显示过程，停止中止 SSE。文字实时追加，思考与工具详情折叠，子 Agent 按调用树嵌套，节点和循环放入过程区。执行过程收起时，以 muted 次要文字概括最新运行步骤，优先等待用户回答与当前工具/模型/子调用；展开后隐藏重复摘要。子 Agent 详情提供主 Agent 交付任务与输入上下文，消息身份映射为可读名称，只有用户能查看，不加入公开群聊。进度展示节点实际名称及可读循环轮次，不展示内部节点 ID 或缓存 frame 路径；名称随事件保存，旧记录优先从对应 Agent 图恢复，否则显示步骤序号。失败后未结束的循环同步为失败/取消，不保留运行中。

## 会话成员与角色扮演

每个会话可展开，下面是主 Agent 过程和已调用的子 Agent；动态成员按会话成员身份显示，普通图调用按 Agent 身份聚合。点击成员只查看它及其后代调用，不显示同级成员的私有思考/工具过程；重复调用在该成员页面依次保留。返回主聊天显示各 Agent 的最终输出，输入始终继续主会话，不直接越过协调者向成员发送私聊。

多角色扮演 ChatBox 把校验成功的可选字段 JSON 分别投影：语言为强调边框对话框，神态/语气为并排信息卡，动作与感官为独立框；缺失或空字段不占显示空间，至少一项有实际内容，允许只输出动作。旁白把已公开对话和动作写为连贯小说段落，以单独正文显示，不展示五项标签。角色使用头像加姓名的对话格式；28px 头像与普通助手头像共用尺寸和样式，姓名及内容从普通助手正文的同一位置开始。不使用关系网人物卡片。优先用 classId/entityId，再用唯一 name 匹配当前世界，旁白无世界绑定；当前头像取名字首字。

## 人类参与与插话

角色会话输入区可选择“旁观”或“扮演角色”，后者填写角色名；生成中不能直接改身份，但始终可以输入并发送“插话”。此时右下角发送保持插话动作，旁边保留停止按钮；普通 ChatBox 继续使用原位发送/停止切换。空输入不可插话，Enter 与按钮遵循同样规则。

插话显示为右侧用户气泡，带身份、复制和生成结束后的编辑入口，位于实际完成发言之间，不能把之后的发言按调用开始时间移到插话之前。存档同时保留普通用户消息与 run 内定位事件，展示时只呈现一次。编辑重发裁掉所属运行中插话后的输出，并恢复发送前会话状态。当前用户扮演角色由用户提供发言，AI 不代演；主 Agent 根据上下文决定下一位，角色可连续多轮交流，等待用户时结束本次生成。

## 实例修改与新增提议

官方修改建议展示带单列行号/上下文的 Git 风格差异，使用主题 success/danger 色，右下角“保存修改 / 拒绝”；pending 不表示世界已修改。过程折叠卡片使用主题面板、图标、状态徽标与展开箭头，官方工具显示中文名称。实例建议默认收起，摘要展示对象名称、状态和全部新增/删除行数；展开查看差异及保存/拒绝按钮。相邻同类新增/修改提议默认合并折叠，提供全部保存/全部拒绝，已保存提供单项回退和组回退；批量失败不部分提交，冲突提示保持原状态。

## 连续工具组

连续工具调用默认合并为可展开工具组，显示次数与组状态，组内保留各调用详情；正文、思考、建议或子 Agent 分隔组，不跨调用作用域合并。

## 正文与差异排版

差异正文自动换行，连续编码与无空格长文本也不得撑宽页面，行号列保持对齐。助手最终正文、流式正文及服务返回的思考内容使用 Markdown/GFM 渲染，支持标题、列表、引用、表格和代码块；工具 JSON 与差异保持原始文本。

## Token、费用与消息定位

用量集中在右下角 ChatUsagePanel，逐模型请求显示输入、缓存、输出、费用和累计；用户消息轮次和模型过程可显示对应请求用量。这些数字来自完整请求，包含系统词、历史和技能，不是单段用户文字的分词。子调用计入总量，按请求身份合并，币种分组，缺 usage 或价格明确标未知。计价数据与公式见 [聊天数据](../data/chat.md#请求用量与价格快照)。

浮窗收起为一个图标外壳，从右下向左上改变宽高；展开后隐藏入口，右上 × 关闭，关闭返回入口焦点。内部独立滚动，收起内容 inert/aria-hidden；不使用第二层按钮背景、阴影或缩放。减少动态效果时直接切换。

ChatMessageRail 的定位点在左侧垂直居中，超量可滚动；每个点对应实际显示消息，预览序号和文字，点击定位并高亮当前阅读位置。跳转后暂停自动跟随，回到底部恢复。

## 用户消息操作

用户消息下方显示主题编辑、复制图标。编辑填回输入框，可取消；确认重新发送时替换该消息并重新生成后续对话，已采纳的世界修改不回滚。生成时禁用编辑，复制仍可用；复制原始文本并显示成功/失败反馈。用户消息按纯文本展示，保留用户主动输入的换行，不额外插入前导空白。消息协议与建议规则见对应功能文档。

## 用户提问卡片

向用户提问显示主题面板、问题 Markdown、可点击选项和自填回答输入框。用户点击选项立即提交其完整文本，也可提交非空自填文字；提交后禁用重复回答，完成事件保存并显示回答。问题打断连续工具组，不藏入折叠详情；子调用问题在主聊天也保持可操作，在过程详情中保留所属调用。运行停止、失败或重启中断时禁用控件，历史问题与回答继续可读。

子成员定向修改与整实例修改使用同一种提议卡片，显示目标路径说明，沿用同类相邻合并、批量确认和回退。

文件提议复用差异卡片，以 FilePen 标识，显示路径、单列行号和增删数，保存/放弃及安全回退沿用提议接口。工具过程使用对应 ToolIcon，而非统一 Wrench；混合类型折叠组可保留通用图标，展开后每项保持职能。提问卡片使用 UserCheck，支持点击选项或自由回答。
