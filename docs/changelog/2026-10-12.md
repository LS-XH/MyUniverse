## JSON 唯一存档与非阻塞任务重构

按用户新契约将世界对象、结构、来源/执行元数据、视图、聊天和应用配置统一为完整 Workspace JSON 自动存档。启动在后台解析/校验/规范化 JSON，不再读取外部 Markdown、Schema、视图和函数脚本来覆盖存档；archiveVersion=2 首次写入时保留 workspace.before-json-primary.json。删除旧 Markdown 冲突/授权替换状态及旧原生混合保存入口，拆分 checkpoint_workspace 与 export_workspace；限定导出不覆盖完整存档，也不导出无关脚本。保存键导出、刷新键导入，独立重新计算函数不先导入正文。

Worker 承担 JSON 编码/加载、Markdown 解析、预览/差异、JS/Flow 与用户 JS Tool；Python 保留原生子进程。运行按取消信号隔离通道并限制空闲线程数量，脚本实际开始后计 10 秒硬超时，取消可终止同步死循环。原生读取、存档与导出进入阻塞线程池。自动写入有合并与调度间隔，持续输入不无限延迟存档；导出只等待发起修订，后续编辑独立存档。

导入完整校验后逐实例合并并让出 UI，允许已完成卡片继续编辑，保留未变化引用；最后处理顺序/删除并检测并发冲突，取消保留已完成内容。导入不占用整个 JSON 写入队列，计算任务后续只定位当前绑定，不重复扫描工作区。函数重算复用生成成员原 ID 和原插入位置，未变化树共享引用；来源协调只检查变化实例，声明变化才完整校验。实例卡片拆为 memo 组件，命令使用最新状态以避免旧闭包覆盖后续结果。

## 纯文本 Markdown 展示与填入 JSON

按新的数据契约，Markdown 标题不再输出函数名 HTML 注释，Class 键和值仅展示实例名；成员 ID、Schema、引用含义、函数来源与执行状态继续保存于工作区 JSON。用户 Text/Content 中原本的普通 Markdown 链接不按 Class 转换。预览位置索引与正文导出共用同一展示规则。

提取 markdownSyntax.ts 共用标题、围栏与转义规则，新增 markdownImport.ts 的填入模型；后台 parse、刷新和选择文件导入统一使用填入入口。Class 键/值按当前位置的 Schema.classId 解析，完整世界目录用于跨类查找，新实例预先建立目录以支持本次文档中的前向引用；缺失引用或同名歧义报错。旧注释兼容读取，但不能凭它创建函数所有权。

保留文件中未包含的实例、固定成员、重复项与递归分支；原顺序保留，新实例/成员追加。重复项先整体预留相同内容的 ID，再匹配其余修改，避免先出现的新值占用后面的生成项身份。相同值保留 JSON 来源、执行记录和引用后缀；改动值复用可匹配的 ID，但移除函数来源及失效执行状态，作为用户内容，解绑不会再按旧来源清理。显式空正文可清空一个值，缺失标题不会清空。导入按名称填充，不把改名或文件缺失当作删除，改名和删除仍在对象编辑器完成。

刷新只填入对象，不自动重新计算函数；独立重新计算保留原追加范围与事务校验。严格替换解析继续用于脚本和建议的只读/结构校验，不作为文件导入的删除规则。更新导入确认文案、顶栏说明、README、总体设计与 UI/数据/功能文档。
