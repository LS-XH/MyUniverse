# MyUniverse 总体设计

## 产品目标与范围

MyUniverse 是以世界对象为基础的小说创作工作台。人物、世界观、关系、地点、事件、章节和插图属于同一世界；多个世界相互隔离。长期目标是让 Agent 在用户掌控的数据、模型与工具上完成设计、写作和绘图。

当前使用 React、TypeScript、Vite 和 Tauri 2。主程序维护结构化对象，Markdown 为可读、可由外部编辑的内容表示；脚本、工作流和视图复用同一套对象接口。Agent 使用项目自身的 Graph 执行器，数据线同时表达执行依赖，支持循环、惰性条件和受限 Multiagent 调用；无需另拉执行线，也不依赖 LangChain/LangGraph。

本文件维护产品全貌。细节入口见 [文档目录](docs/README.md)，每项设计在对应专题内更新；上下文过程和历次验收只写入 [修改日志](docs/changelog/README.md)。[原始 Planning 副本](<Planning - 副本.md>) 是历史需求，不作为当前实现规范。

## UI

### 应用框架与导航

最左侧操作栏依次为创作、插件、模型、设置。侧栏承担对象导航，主区承担当前对象操作，顶栏显示路径和页面动作。导航树无缩进层级线，保留缩进与右侧箭头；单击打开页面，箭头或双击展开，右键只打开菜单。页面切换保留各自的滚动、展开、视角和倍率。

创作中按世界组织集合、文件及界面。插件按技能、函数、工具组织，可用文件夹混排；模型按 LLM、Stable Diffusion、Agent 分类；设置管理主题。插件路径包含分类、父文件夹和当前项；模型路径包含类型集合和当前项。

集合页面保留标题、对象卡片和创建入口。脚本及工作流页面以编辑器为主体，采用紧凑工具栏。页面动作复用同一命令，不为顶栏或右键菜单另写业务逻辑。详见 [页面 UI](docs/ui-interactions.md)。

### 创作页面

- **集合**：组织子集合、类文档、关系网和地图；组织层级不改变磁盘文件位置。
- **文件操作**：实例以卡片显示，键、值与函数添加的子成员使用同一套成员卡片；支持名称搜索、编辑、排序、引用选择与 Markdown 双栏。
- **属性配置**：编辑类的键值类型、重复成员、子结构、提示文本及 Function 绑定；同一父对象内排序，并同步实例字段顺序。
- **关系网**：人物专用视图，按人物结构读取姓名、势力、关系和分组背景；关系 Object 中的可重复 Class-关系键在同一连线上逐行显示，颜色取第一个可见关系值，可切换函数生成关系的可见性；连线及详情编辑写回源对象，布局独立保存。
- **地图**：按父类实例生成标记，绑定背景、名称、坐标；支持平移、缩放、拖动标记和打开源实例。
- **聊天**：会话在创作树中展开，可选 LLM 或 Agent；回复与工具建议保持发起世界和会话身份。

关系网定制于人物类别，不提供父文件类型及显示元素绑定；地图保留可配置的对象投影。详见 [投影视图](docs/interface-views.md)。

### 插件页面

Function 与 Tool 共用代码编辑器、对象调用助手和紧凑配置/测试入口。Function 工具栏显示“函数 - JS 脚本 / Python 脚本 / Flow - 名称”；Tool 的参数 Schema、MCP 注释等放在“配置”浮层。官方 Tool 为程序维护的只读模板，不能编辑、删除或移动。

Skill 集合入口保留，技能执行与插件安装/发现尚待实现。

### 模型与工作流页面

LLM 页面配置连接及请求参数。Agent 与 SD 共用节点画布；Function Flow 复用编辑手势，但具有独立的图结构和函数契约。

右侧节点库固定标题和搜索区，树内容单独滚动，标题旁可展开/收起所有目录。变量池与节点库处于同一父容器，从底部展开并挤占树高度。配置、运行浮层位于节点库左侧；库关闭时移到画布左侧，点击空白收起。

卡片名称属于节点类型，不能按实例用途自定义。相同语义的输入与输出合为一行，显示类型图标；变量可显式绑定到端口。仅基础类型能直接填写值，封装类型显示引导拖入变量的参数槽。完整交互见 [工作流编辑器](docs/workflow-editor.md)。

### 主题、反馈与拖动

普通对象颜色来自主题；关系网等有独立颜色配置的视图允许配置覆盖。悬停、点击、拖动、展开收起均有渐变反馈，并尊重减少动态效果偏好。

拖动遵循不变性原则：默认保持对象形态，只在进入特定区域时转换。树和列表通过动画挤位表示落点；普通画布变量使用普通节点移动逻辑，连线同步跟随。节点库拖出对象由行卡片变为实际卡片尺寸的空白占位矩形；所有预览整体缩放。变量进入父卡片才收缩成行，进入兼容槽则由同一拖动外壳变形填入，松开才提交引用。详见 [通用设计原则](docs/design-principles.md)。

## 数据结构

### 世界与对象

Workspace 管理世界、主题、插件、模型和 Agent。World 是创作项目隔离单位。每个 ClassDocument 对应类 Markdown 和属性 Schema；一级标题是类，二级标题是实例，后续标题为递归成员。

Value 类型为 Object、Class、Data、Text、Content、Integer、Decimal、Null；Key 类型为 Text、Const、Class。Object 是 Schema 约束的成员集合；空 Value 可表示无内容项。Class 引用指向当前世界内的类实例，以 Markdown 链接呈现。Data 保留既有命名，日期格式为 YYYYMMDD。

普通 Class 键/值仅引用实例身份，不选择原值或 Function 结果。函数添加值是带来源标记的普通成员，返回值不构成世界子对象。

类、实例、Schema、成员、树节点、视图均保留稳定 ID。导航父节点与视图数据父类分开，名称不承担唯一身份。详见 [数据模型](docs/data-model.md)。

### 类型与变量

世界 FieldValue、Function TypedValue、工作流变量是三个不同层次，不可直接混用。Function 使用固定 self/input 和 void 执行，通过 add 参数的 TypedValue 及既有 Schema 规范添加内容，返回值不参与世界修改。工作流使用 String、Number、Boolean、Messages、Image、Tools、Agents 七种变量类型，禁止新建 ANY 变量。

变量持久化为 `{id,type,value}` 信封，端口只传类型对应的值。读写共用一个变量节点；方法产生新值，只有显式接入变量 value 或绑定输出才写入运行变量。相同名称的声明类型必须一致。Agent 按世界隔离记忆，整次运行成功后才提交，失败与取消不提交局部记忆。

Messages 管理 system/user/assistant/tool、工具调用及配对结果；Image 管理图片资源；Tools 只保存注册 Tool 的稳定 ID。详见 [工作流类型](docs/workflow-types.md)。

### 持久化与同步

桌面数据在 exe 同路径的 `user` 下：世界文件平铺于对应世界目录，集合与插件文件夹是虚拟组织。浏览器使用 localStorage。

全部界面操作（增删查改、重命名、函数追加、设置与插件配置）只修改内存 JSON。Markdown 仅在程序加载或明确刷新时读入，读取正文覆盖对应 JSON 内容；仅通过保存当前文件或保存全部写出，保存前不再读取、合并正文。实时预览只展示内存序列化结果。Ctrl+S 保存当前文件/配置，Ctrl+R 刷新当前文件/配置；创作刷新后重算函数，结果仍留在内存。切页保留草稿，不自动持久化或计算函数。未保存标记按当前序列化内容与最后成功加载/刷新/保存版本的差异判断，不按内部运行元数据或时间戳判断。Schema 是唯一属性结构来源，未知正文项忽略，不反推声明。同一世界文件保持平铺，由 JSON 管理逻辑组织。详见 [Markdown 与存储](docs/markdown-sync.md)。

## 功能

### 创作基础与默认模板

新世界内置人物、关系、势力、地点、事件类，以及世界观、人物、事件、章节、插图集合。默认类不可删除，内容可编辑；章节与插图集合保留扩展入口。模板具体成员见 [数据模型的默认模板](docs/data-model.md#默认模板)。

### Function、Tool 与世界接口

JS/Flow Function 与 JS Tool 在主程序执行，按稳定 ID 使用同一对象门面，按需转换 Markdown。接口写入先暂存运行草稿，成功校验后与并发 UI 修改合并为创作草稿，由用户明确保存；不直接把可任意改写的 React 原始对象交给脚本。

Function 服务于对象成员扩展，固定输入和类型化添加参数；绑定调用为 void，通过统一 add 接口向绑定成员及其任意深度子对象添加符合既有 Schema 的可重复值，不得修改或删除已有值。新增成员复用普通成员显示，但由函数维护，用户不能编辑或直接删除，内部来源标记用于解绑、换绑、删除函数时清理；生成成员上方显示“函数名 →”来源提示，不创建函数名成员或派生返回容器。Markdown 在生成对象标题旁写入可读函数名注释；原始输入排除新增成员，绑定函数不随编辑、改名、切页或布局变化自动执行；刷新时重新读取当前文件并显式计算全部绑定函数。Tool 服务于模型，自由 JSON 参数与可传输结果，配置描述及 MCP annotations。Python 保留桌面子进程，用快照读取和操作日志接入主程序写入。详见 [Function](docs/functions.md)、[脚本与 Tool](docs/script-runtime-and-tools.md)。

官方九项 Tool 包括查询类名、类结构对象/Markdown、实例名称、实例对象/Markdown、递归 key、提交修改建议与提议添加新实例及内容。提议只产生聊天事件，用户决定是否保存；同类相邻提议可合并折叠、全部保存或拒绝，已保存项支持冲突检查后的回退。两类提议参数均为 className、instanceName、markdown。详见 [官方 Tool](docs/official-tools.md)。

### 模型、Agent 与绘图

基础“LLM 模型”输入 Messages 及显式 Tools、Agents，请求一次并输出本轮 assistant Messages。系统词由 Messages 维护；ToolCalls 按能力身份分派工具与子 Agent，返回工具消息片段，循环与惰性条件编排多轮交流。兼容“LLM 模型（自动 ToolCalls）”保留自动交流；聊天系统词仅用于直连模型。

Agent 自带可编辑 ToolUse 示例，展示显式消息、工具执行和成功后保存记忆。SD 从 ComfyUI 加载实际节点目录，在主程序求值前处理，再提交 API 图执行与取图。详见 [模型与 Agent](docs/models-and-agents.md)。

## 当前边界与后续方向

已经具备对象化 Markdown、双向同步、投影视图、JS/Python/Flow Function、JS/HTTP Tool、官方工具建议、模型连接、显式 Agent 与 ComfyUI 桥梁。接口接入不等于真实服务联调完成，真实模型与 GPU 需配置服务验收。

聊天已接入 POST SSE，统一选择模型或 Agent，展示服务返回的思考、工具、嵌套 Agent 与待确认实例差异；根成功统一提交子调用记忆。图运行面板和模型测试仍用非流式 HTTP。后续方向包括 Skill、插件安装/发现、完整 ComfyUI 前端布局导入、自动章节写作和插图归档。图片像素加工、远程 MCP 连接及对外 MCP 服务器亦尚未实现。关系网双实线渲染仍需完善。

设计维护、代码入口与验收方式分别见 [文档维护规则](docs/documentation-guide.md)、[架构](docs/architecture.md)、[开发与验证](docs/development.md)。

### 人物关系网的个人视图

关系网支持双击人物进入个人关系视图：本人居中，直接相关人物环绕，过滤无关人物与边；返回或 Esc 恢复完整视图。个人布局独立于完整关系网的持久化布局。关系连线格式按关系类型提供可见性开关，重复关系过滤后使用第一个可见关系的格式，展示全部可见关系文字。关系连线格式及背景块格式默认收起。

### 未保存状态的实例粒度提示

文件操作类型的实例卡片按已保存快照独立判断改动，名称右侧使用主题色发光圆点提示。树视图文件和父集合继续汇总状态，仅增加圆点，不改变名称字号和字重。实例内容、函数生成对象、标签及排序变化纳入比较；成功保存或撤回修改后重新判定。

### 创作导航的项目根层级

创作树以每个世界项目为顶层文件夹，移除“我的项目”父菜单。创建世界与项目根行向左对齐，缩进仅从项目的子对象开始，增加可显示名称的空间。

### Markdown 作为实例内容来源

桌面端的实例及成员内容以实际 Markdown 为权威来源，JSON 负责组织、身份和配置。已声明重复结构中的新增键值必须由文件恢复，不依赖缓存里是否曾有该项；旧兼容逻辑不得改写用户当前 Schema。加载失败显式报错，不静默使用旧 JSON 内容。磁盘读取的来源标记以文件为准，界面生成值继续保持只读。

### Markdown 双栏的差异展示

右侧正文参考提交差异界面，以最近成功保存的文件模型快照为基线显示新增和删除行；绿色 + 表示新增，红色 - 表示删除，浅蓝背景标记当前选中对象及下级内容。删除行是只读展示，不能进入编辑正文或保存输出。保存重置比较基线，后续草稿改动继续显示差异；三种背景均可由主题配置。

### Function 内部状态与正文的读写方向

Markdown 只记录普通实例成员及生成标题旁的 `<!-- 函数名 -->`，不包含 function-sources 或 function-origin 的内部身份表。函数来源、绑定身份和执行状态保存在后台 JSON。刷新时正文覆盖旧 JSON 对象内容和来源，保存时才由当前对象模型写回正文；来源缺失或歧义必须明确处理，不用缓存旧值代替文件。重算事务只替换当前绑定自身生成值，保留用户原值及其他绑定；失败整体回滚。旧注释和索引兼容读取，保存转为新格式。
