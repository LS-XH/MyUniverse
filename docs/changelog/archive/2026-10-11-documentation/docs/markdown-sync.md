# Markdown、持久化与同步

## 存储职责与文件布局

世界实例内容可由 Markdown 恢复，不把 workspace.json 当唯一内容来源。JSON 管理结构、身份、组织和应用配置，Markdown 管理可读内容；读取与写入复用同一模型。

```text
user/
  workspace.json
  functions/<function-id>.js | .py | .flow
  images/<filename>
  worlds/<world-id>/
    <class-file>.md
    <class-file>.schema.json
    <view-id>.view.json
    world-index.json
    关系网.json / 地图配置.json / 聊天框配置.json（兼容及聊天配置）
```

桌面基准为 exe 同路径 user；世界目录按 worldId 隔离，类/视图文件平铺，集合和插件文件夹不产生物理层级。world-index 是世界组织清单。浏览器使用 localStorage 的 myuniverse-workspace-v1，不读写这些桌面文件。

Function 脚本文件由统一桌面保存导出，路径不因逻辑文件夹或改名改变。模型、SD、Agent、用户 Tool、主题和插件组织存 workspace.json；官方 Tool 由程序注册，不序列化为用户定义。

## Markdown 格式

```markdown
# 人物

## 角色一

### 人物性格

谨慎

### 人物势力

#### 势力名称

[示例势力](势力列表.md#示例势力)
```

一级标题为类名，二级为实例名，三级及更深为成员 Key，正文为 Value；Object 递归子标题，Null 不写正文。类名与 fileName 分开，默认“人物 / 人物列表.md”等是合法映射。

Class 引用为 `[实例](类文件.md#实例)`，包含必要转义。数值与日期以文本写入，Schema 决定类型；没有声明时不能凭数字外观猜 Integer/Decimal。重复成员保持同一 Schema 声明、独立成员身份和出现顺序。

Content 可以包含 Markdown 标题、代码围栏及引用；解析须结合 Schema 与围栏判断，不把长正文内所有标题误当结构。提示文本保存于 Schema.placeholder，不写成用户真实内容。不同层次路径、重复键与引用匹配需保留既有稳定 ID。

### Function 生成成员与来源元数据

函数通过 add 生成的成员使用普通属性标题、正文和子标题；对象编辑器显示“函数名 →”，Markdown 标题旁仅写入 `<!-- 函数名 -->`，解析时从成员键剥离。

```markdown
# 类名

## 实例

### 已声明的可重复属性 <!-- 函数名 -->

普通值
```

内部 `functionOrigin={functionId,name,bindingFieldId}`、成员 ID、Schema ID 和 `functionRuns` 保存在工作区 JSON 中，不导出 `function-sources`、`function-origin` 或执行过程索引。正文标记区分生成成员与用户成员；解析先以声明结构读取正文，再复用匹配的 JSON 身份。缺少 JSON 来源记录时，按函数名和当前实例内的绑定作用域重建来源；来源不唯一时明确报错，不猜测删除对象。函数名的特殊字符使用实体转义，避免破坏注释。

刷新和启动时，实际正文覆盖旧 JSON 中的成员内容和来源标记；旧 JSON 不得补回已从正文移除的成员或阻止外部有效变更。JSON 只辅助确认身份和执行状态。刷新后绑定函数重算仅替换该绑定拥有的生成对象，用户原值和其他绑定结果保留；执行失败保留旧有效结果。保存才把当前对象模型序列化回正文。界面源码及导入保持生成对象只读约束，外部重读以文件为准。

旧 `<!-- <!> 函数名 -->`、function-sources 短索引和 URL 编码 function-origin 仍可读取，保存统一迁移为仅有函数名的注释，不额外触发自动写盘。旧函数结果标题和 function-value 元数据只为兼容解析，不再输出。来源与清理规则见 [Function](functions.md#显示来源和绑定生命周期)。

## 转换与加载

model/markdown.ts / markdownParser.ts 提供文档、实例、成员序列化与解析；exportFiles 输出正文、结构、视图和组织配置。传入既有 ClassDocument 与 World，按 Schema 解析、保留身份并校验引用。

实例标签定义 labels 与关联 entityLabels 是 ClassDocument 的样式 JSON，只通过 workspace.json 保存；Markdown 文本与属性 Schema 不增加标签字段。解析正文保留既有样式 JSON，稳定实例 ID 保持染色关联；副本生成新实例/成员 ID 后显式复制同类标签关联，删除实例清理对应关联。

loadWorkspace 先读取/规范化工作区，再读取已注册 Markdown、Schema 和视图配置。启动时无效外部文件明确报错，不静默回退到旧 JSON 实例值，不覆盖原文件。

Schema、Markdown 与已注册视图 JSON 只在加载与显式刷新阶段读取。不进行周期或焦点恢复刷新，不实时发现未知 .md，也不凭正文推断 Schema。这是当前边界，不能把“监测 Markdown”扩写为完整目录同步。

### 外部 Markdown 的结构边界

属性配置是唯一结构来源。读取、导入、编辑 Markdown 不推断新属性、不增加“内容”属性、不把重复标题自动改为可重复，也不根据脚本标题新增函数绑定。未知属性及其子树在对象解析时跳过；未声明函数结果块同样跳过。已声明的 Text/Class 动态键和可重复成员仍按其已有声明解析，已有 Content 内的正文标题仍属于文本内容。未配置时不从 Markdown 反向生成 Schema。

非重复成员的多余同级标题忽略，保留第一个匹配项；已配置固定成员缺失时沿用现有空值恢复规则，不删除配置。模型修改建议额外使用严格未知结构校验并拒绝越界建议。

## 界面双向编辑

对象编辑实时生成源码并按字段位置定位；源码编辑使用短防抖解析（约 350ms），成功后更新同一文档对象。无效草稿继续显示错误，保留最后有效对象，明确保存时阻止错误内容落盘。

源码列的开关、高亮和页面恢复由 [文件 UI](ui-interactions.md#markdown-双栏) 负责。创作内容只更新内存草稿，不定时写入、不在切页或焦点恢复时重新加载。保存当前文件（Ctrl+S）先立即解析未完成的源码草稿，提交当前类的 Markdown、Schema 和 JSON 样式/执行状态；其他创作文件使用已保存快照，不夹带其他草稿；桌面写入输出只包含目标正文/结构或视图配置及必要组织清单，不重新写其他正文、Schema 或视图文件。非创作配置保存不导出世界文件。保存全部提交全部当前草稿。新世界首次保存会建立世界初始文件与组织清单；已存在世界的集合保存更新组织清单，现有其他文档正文仍使用已保存基线。

刷新（Ctrl+R）以磁盘文件及 Schema 替换当前文件草稿，取消未完成的源码解析；其他文件的草稿保留。刷新后计算当前文件全部绑定函数，结果仍在内存等待保存。未保存过的文件先保存再刷新。浏览器刷新读 localStorage 的已保存快照；桌面刷新按注册文件名读取，不发现未知文件。插件、模型和设置同样只修改内存 JSON，保存配置时使用已保存世界，不夹带创作修改；Ctrl+S 保存配置，Ctrl+R 读取配置 JSON 和脚本，不读取世界正文。异步保存返回使用 applySyncResult，合并等待期间界面继续编辑的内容。

## 手动读写边界与版本基线

界面中的增删查改、重命名、属性配置、函数追加、插件、模型和设置操作全部修改内存 JSON 对象；实时 Markdown 预览是内存对象的序列化结果，并非磁盘文件被实时写入。切页、失焦、定时器和脚本提交不触发持久化。

启动和显式刷新是磁盘读取入口。刷新时正文覆盖 JSON 中对应文件的内容；其他文件草稿保留。保存当前文件和保存全部是写入入口：只序列化提交时的对象快照，不重新读取、解析或合并 Markdown，不按外部修改重试。Rust 直接原子写入提交内容，不读取正文进行 expected 比较。外部修改要先刷新才会进入内存；未刷新直接保存时，当前提交覆盖目标文件的磁盘版本，这是明确的操作语义。

上次成功加载、刷新或保存的对象快照作为版本基线。文件未保存标记比较当前对象序列化后的正文及该文件的配置；实例标记比较实例正文、顺序与标签。执行记录、运行时间或纯内部身份变化不单独造成正文未保存标记。内容改回基线后标记消失，因此不用文件时间戳推断版本先后。没有刷新时，程序不会侦测外部正文改动。

读写共用串行队列，排队保存按提交顺序写各自快照。applySyncResult 仅协调异步完成期间新产生的界面编辑，保留较新输入，不承担磁盘三方合并。失败保留草稿及旧成功基线，不宣称保存成功。

## 导入与脚本

导入解析所选 Markdown 并修改当前内存文档，保持身份和已声明结构；保存后才写入目标正文。未知属性及子树忽略，不从正文生成 Schema。有效导入也可通过明确保存替换损坏的旧文件，无需保存前读取旧文件。

ScriptHost 的 autoSave:false 禁止脚本成功提交和 app.storage.save() 请求隐式写盘。Function、Tool、Agent 生成修改经结构校验进入主程序内存；用户保存时统一落盘。刷新后函数重算结果仍留在内存。

同一世界文件继续平铺在 world 目录，JSON 管理逻辑组织；模型、主题、插件和 Agent 配置共用 workspace.json，保存配置会提交当前非创作配置快照。保存创作当前文件使用已保存的非创作配置，不夹带配置草稿；保存全部统一提交所有当前对象。图片生成等外部工具产物的输出不属于正文保存流程。

## 代码入口与验收

storage.ts：loadWorkspace、reloadCreationFile、refreshWorkspace、reloadPreferences、saveWorkspace 和 applySyncResult；manualSave.ts：提交投影与内容差异标记；AppRoot：手动操作及快捷键；lib.rs：显式读写与原子写入。

验收包括加载和刷新正文优先、保存零正文读取、损坏文件在刷新时报错而明确保存可替换、队列按提交顺序写入、配置保存不读写世界正文、单文件范围隔离，以及函数生成内容只随明确保存写入。

### 文件内容权威与重复成员加载

桌面端仅在加载和显式刷新时读取实际 Markdown；实例名称、成员键和值、重复项的新增和删除均以文件正文为依据。Schema 文件定义允许的结构，不能从正文推断新属性；结构内声明的重复 Class 键，即使没有出现在旧 JSON 快照中，也必须读取。工作区规范化不得按旧版人物模板改写当前 Schema 的 Object 类型。

JSON 保留组织、样式、稳定身份及执行状态，既有成员可用于匹配 ID，但不得约束磁盘正文必须与旧值相同。磁盘解析按正文函数名注释及 JSON 身份记录恢复函数来源，不依据缓存中的来源否决新正文；界面仍禁用生成成员编辑，源码编辑与导入保留只读校验。加载文件解析失败时明确报告文件与错误，不静默回退 JSON 实例内容，且不覆盖文件。

单文件刷新只限制磁盘读取与草稿替换范围，不缩小解析所需的世界类目录。跨类的 Class 键和值继续使用完整世界目录识别，避免刷新人物文件时因缺少关系类型或势力类型而丢弃已声明结构中的成员。
