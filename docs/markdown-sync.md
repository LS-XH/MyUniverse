# Markdown 双向编辑

更新日期：2026-10-09。需求见 [Planning](../Planning.md)，模块职责见 [架构](architecture.md)，操作说明见 [界面与交互](ui-interactions.md)。

## 文件角色

桌面版数据位于程序旁的 `user/worlds/<世界 ID>/`。`.md` 文件保存实例名称与属性内容；`.schema.json` 保存属性类型、可重复性和 Class 指向。`user/workspace.json` 保存项目树、稳定 ID、界面配置、主题和缓存。启动时会读取每个类的 Markdown 来还原实例，因此外部 Markdown 内容优先于 JSON 中缓存的实例内容。缺少 Markdown 的旧项目会用缓存创建文件。

## 格式

```md
# 人物

## 林青

### 人物性格

谨慎

### 人物势力

#### 势力名称

[青山](势力列表.md#青山)

#### 势力地位

队长
```

一级标题为类，二级标题为实例，后续标题按层级表示属性。类型使用当前属性配置。未配置的属性会补充到配置中：有子标题的属性为 Object，纯文本为 Text/Content，可识别的实例链接为 Class。未配置类型的数字默认保留为文本，不自动猜测日期或数字类型。相同的属性标题可以成为可重复属性；实例名称必须唯一。

二级标题下、属性标题之前的正文会收纳为“内容”属性。一级标题下不支持类正文，应放到二级实例标题下面。导入时的同级重复属性、空属性、引用链接、嵌套属性和代码块均可读取。已配置为 Content/Text 的属性内部更深的标题作为正文保留。序列化会转义正文中的标题行，防止下一次读取时被当成实例或属性；代码围栏中的标题保持原样。超过六层的对象使用更多 `#`，仍可由本程序往返读取，但通用 Markdown 阅读器可能把这些层级当成普通文字。

## 导入 MD

每个文件操作页右上角提供“导入 MD”。选定文件后先查看识别结果，确认后替换当前类的实例内容。当前类的 ID、文件名、内置保护状态与类型配置会保留；新增属性会补充配置。结构或已配置的数字/日期类型不合法时，会报告错误。已损坏的当前文件也可以通过确认导入一个有效 MD 来替换修复。

## 双栏源码编辑与行定位

主界面右上角固定的 PanelRight 按钮切换独立的 Markdown 双栏编辑。源码标题区延伸到顶栏顶部，包含文件名、保存状态和该按钮，开关不随分栏移动。打开时收窄留白并为源码列分配空间，关闭按钮或 Esc 可关闭；点击空白或编辑左侧对象不关闭。源码随对象修改和外部文件重新读取更新，支持直接输入。# 标题按级别增大字号、加粗，保持原始语法；代码围栏和转义标题不应用标题样式。输入区域支持换行、纯文本粘贴及中文组合输入，行定位按真实布局滚动。

- 左侧选中或修改实例名称：定位并高亮对应二级标题。
- 左侧选中或修改对象键：定位并高亮对应属性标题，包括 Class 引用键。
- 左侧选中或修改属性值：定位值所在行；多行值可高亮整个值范围，空值定位到属性标题。
- 较远的源码行自动滚动到可见区域，编辑区与高亮层保持滚动同步。
- `markdownLocations` 使用实例/字段 ID 关联行位置，区分不同实例中的相同键及嵌套字段。
- 默认高亮为透明浅绿色；自建主题的“Markdown 当前行高亮”支持 ARGB 配置。

右侧停止输入 350ms 或离开编辑框时解析草稿，合法内容同步到对象，再走正常的自动保存流程。解析期间保留编辑文本；重新选择左侧字段时，有效源码规范化为对象对应格式。格式有误时显示提示，当前页面保留草稿及最后有效对象，修正后才能提交；未解析成功的草稿不会写入文件，也没有跨页面/重启的草稿保存功能。

外部刷新或后续左侧对象修改会更新源码，因此无效草稿不应当作独立文件版本。磁盘写入仍受下述三方合并与错误保护约束。

## 拖动排序与模板兼容

实例卡片可通过手柄上下排序，序列化按实例数组顺序生成二级标题，重新读取保持顺序、稳定 ID 与属性内容。属性条可在同一父结构内排序，写入 `.schema.json` 并调整实例字段序列；禁止跨父对象移动。两种排序共用指针交互，显示跟随光标的半透明副本，并以完整尺寸占位实时挤开其他项。拖动期间不写入数据，松开后提交顺序，取消时恢复。适用于浏览器与 Tauri，避免原生拖放拦截。

人物模板中的“关系”值是 `Class-关系`，以关系实例链接保存；人物关系子项的键是 `Class-人物`，以人物引用标题保存。旧文本关系能匹配现有关系实例时自动迁移为链接。人物势力使用 `Class-势力` 和文本“势力地位”。关系网连线方向由存储关系的主语实例指向引用的人物实例，不隐式写入反向关系。


## 自动同步

- 对象修改后约 400ms 自动保存。
- 启动时从 Markdown 还原对象。
- 窗口重新获得焦点、页面重新可见时检查文件。
- 页面可见期间每 3 秒检查文件。
- 每次写入前重新读取 Markdown，并比较基线、界面和文件三个版本。不同属性的编辑和独立的新增/删除会合并。
- 后端写入前再次比较文件内容；若读取后文件又变化，会重新读取并重试，最多三次。
- 同一属性双方修改，或一方删除了另一方正在修改的对象时，暂停保存，并提供“采用文件内容”或“保留界面内容”。非冲突修改仍会保留。
- 格式错误、读取失败或外部删除已有文件时，保留界面的最后有效内容并显示错误，不覆盖该文件。修复或恢复文件后重新读取即可。

浏览器预览使用本地存储，可以导入 MD 和实时编辑源码；持续监测磁盘文件仅用于桌面版。属性类型配置在启动时读取，不会持续监测外部 `.schema.json` 编辑。项目树仍由工作区元数据管理，直接在目录中新增一个陌生 MD 不会自动创建文件操作项，请先创建类再导入。

## 验证

`npm test` 运行当前测试集合，覆盖解析往返、引用、深层对象、正文、稳定 ID、字段行定位、属性合并、外部加载、错误文件保护、保存竞态、排队保存冲突、排序往返、模型配置及关系网几何、边缘自动平移速度、缩放锚点和不同高度卡片的动态排序占位。浏览器另验证过左侧改名/改值同步高亮、右侧编辑更新对象及较远行自动滚动。

`cargo test --release --lib`（在 `src-tauri` 内）：真实临时目录中验证写入前内容比较及路径范围限制。

## Function 绑定

所有 Value 类型可绑定多个 Function。原值保留，函数返回值以更深一级的 `[函数名](../../functions/<函数ID>.js、py或flow)` 标题保存；解析时恢复为独立函数结果，不混入普通子属性或原值。对象引用与关系格式实例菜单共享原值/返回值选择。脚本管理、示例、错误处理、编辑行为及运行环境要求见 [Function](functions.md)。

## Flow 返回值与世界读取

.flow 链接与 JS/Python 返回值使用相同的子标题解析、引用和绑定规则。对象读取从已解析世界生成 Markdown 快照，排除当前函数自身旧结果；原始值、成员或 schema 修改使依赖 world 的函数失效，完成时检查版本。生成结果变化不触发世界依赖刷新，以免循环计算。Flow 图启动时从注册 .flow JSON 加载，运行中外部图文件不实时监听。

## 界面变化与序列化的关系

成员卡片化、紧凑引用/短文本宽度、悬停缩放与倾斜均属于展示层，不增加标题层级或修改字段 ID。移除编辑区层级竖线后，Object 仍按原本父子结构序列化；源码层级由对象结构决定，与卡片视觉缩进无关。左侧选择和编辑继续沿 data-field-id / data-entity-id 定位源码。

函数结果只读控件展示 typedValue，不从控件样式推断类型；类型元数据与正文继续按既有规则往返。引用控件旁的使用原值/函数结果选择改变值来源，同行布局只是参数归组。详细设计见 [设计原则](design-principles.md)。


## 界面操作类型的对象投影（2026-10-09）

采用 `World.views[id]: InterfaceView`，每个视图必选父 ClassDocument，显示元素由稳定 ID 路径绑定，支持当前实例与固定对象、Markdown 序列化文本与内容值。关系网和地图共享绑定解析器；源对象编辑写回原 Markdown，布局独立保存到 `<view-id>.view.json`。集合层级是 JSON 虚拟组织，所有文件继续平铺在原 world 目录，另输出 world-index.json 组织清单；旧项目自动补默认绑定，不移动文件。视图配置纳入读取、三方合并与写前竞态检查。详细结构、上下文和兼容边界见 [界面操作类型与数据结构](interface-views.md)。
