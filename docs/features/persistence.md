# JSON 存档与 Markdown 导入导出

<a id="手动读写边界与版本基线"></a>

## 唯一数据源

所有世界对象、Schema、引用身份、函数来源与执行状态、视图、模型、工具、聊天和 Agent 记忆统一在内存 Workspace 中操作，并自动存档至 workspace.json。JSON 的解码、结构检查和规范化在后台执行，错误存档不进入自动写入；JSON 是应用恢复对象的唯一来源；Markdown、schema.json、view.json 和函数脚本文件均为显式导出产物，启动不以它们覆盖 JSON。

旧 workspace.json 直接兼容规范化。首次写入 archiveVersion=2 时，桌面保留原 workspace.json 为 workspace.before-json-primary.json；备份只建立一次，不修改既有 Markdown，不移动 user 目录。

## 自动 JSON 存档

useWorkspaceArchive 合并连续编辑，首个待写修改约 250ms 后启动一次写入；持续输入不会无限推迟存档。正在写入时记录最新修订，完成后按间隔继续调度，避免追赶流式消息时无限占用写入队列。导出只等待发起时请求的修订，随后新编辑继续独立存档。后台线程负责 JSON.stringify，桌面 checkpoint_workspace 使用 spawn_blocking 校验并单文件原子写入完整 JSON。自动存档不解析、不读取、不写出 Markdown，不导出脚本或视图文件。

状态显示 JSON 存档中、已存档或失败；失败保留内存内容并支持重试。尚未完成或失败的存档在退出前提示。导出前等待 JSON 存档完成，不以导出投影覆盖完整存档。浏览器模式使用原有 localStorage，JSON 序列化在后台，但浏览器存储 API 本身仍同步。

## 保存按钮：导出

保留保存当前文件和保存全部入口及 Ctrl+S 操作习惯，语义变为明确导出。当前文件只导出目标 Markdown/配置及必要组织清单，不序列化或验证无关类的正文；保存全部导出全部类、视图、聊天及函数脚本。配置页面可导出其对应 JSON。

exportFiles 支持限定类 ID；后台生成并校验导出内容，桌面 export_workspace 在阻塞线程池写出。导出命令不改 workspace.json，不能用旧的单文件投影覆盖其他类已自动存档的数据。

文件与实例的发光标记表示本会话中相较初始或最近导出快照的差异；它们不是 JSON 未存档指示。比较使用对象字段，不在 React 渲染阶段生成全文 Markdown。存档状态单独展示。

## 刷新按钮：导入

Ctrl+R 在对象文件读取对应的 Markdown 导出文件，按当前 JSON 中的 Schema 解析；不导入旁边的 schema.json，不反推结构。单文件导入保留其他类的当前内容；世界导入顺序处理注册文档及已有视图导出配置。界面配置刷新显式导入对应 view.json；普通非创作配置刷新读取存档 JSON。

导出 Markdown 只展示内容和 Class 实例名，不输出函数来源注释或实例超链接。导入按 JSON 中的属性配置解析类型：相同值保留身份与函数来源，新增或改动值作为用户内容；JSON 中未包含于文件的实例和分支保留。缺失或格式错误的导入文件明确报错。浏览器没有桌面文件路径，需通过“导入 MD”选择文件，不把 localStorage 恢复冒充 Markdown 导入。

解析在后台完成并校验整个目标文档，校验成功后仅合并当前实例，实例之间让出主线程；导入不占用整个 JSON 写入队列，已完成实例可在导入继续时存档。先显示已完成实例，最后保留已有实例顺序并追加新实例，不删除文件中缺失的实例；不提交半个解析对象。整文件初始校验失败不改对象。

导入期间的编辑按稳定 ID 三方合并，独立成员修改保留，重叠修改报冲突而不覆盖。停止导入保留已完成实例和未完成旧内容。全世界导入不是跨文档事务：已完成的文档/实例不因后续失败或取消撤销，均进入自动 JSON 存档。

刷新先导入并填入 JSON，再逐实例重新计算当前文件、视图源类或项目的绑定函数；“重新计算函数”只计算，不导入 Markdown。解析失败或取消导入时不继续计算，后续计算支持取消并保留已完成结果。

## 后台函数与任务边界

JS/Flow 与用户 JS Tool 的计算、JSON 序列化、Markdown 解析、预览与差异生成使用独立 Worker 通道。函数先读取任务快照，在 Worker 中执行世界门面与校验，再仅提交目标实例，使用三方合并保留计算期间的编辑。单次函数调用失败保留旧有效生成值并记录错误，已完成的其他实例不回滚。Python 使用桌面子进程桥。

函数首次扫描限定世界/类，后续只重新定位当前绑定；不在每个任务前扫描完整工作区。普通状态更新不再递归协调全部函数来源，仅协调变化实例，绑定声明或函数集合改变时完整校验。传输后的实例恢复未变化子树的引用，未变化卡片由 memo 跳过渲染。

计算进度按已完成任务推进；停止通过 AbortSignal 终止 Worker 等待及同步死循环，保留已完成实例。单次 JS/Flow 后台执行最多 10 秒，异步脚本自身仍有 5 秒等待上限。Python 的主进程调用不能即时杀掉已开始的子进程，取消后拒绝提交晚到结果；外部网络副作用不属于对象回滚。

## Markdown 预览

右侧 Markdown 是只读导出预览，不参与对象写回。关闭时不生成全文；打开后后台生成源码、位置索引、标题层级和差异行，短时合并连续结果更新。大文件采用共同前后缀、Patience 唯一行锚点和有界 LCS；无锚点时用线性空间单调匹配，保留公共行而不按整个大区块删除再新增。

DOM 按每帧最多 200 行 / 8ms 分批协调，按行文本与出现次数复用节点，更新局部行及样式，不因行数变化 replaceChildren 整个编辑区。删除行是只读比较，不写入导出正文。

## 代码入口与验证

- storage.ts：唯一 JSON 加载、自动存档、限定导出、显式导入与渐进发布。
- useWorkspaceArchive.ts：合并写入、重试、退出状态。
- background.ts / backgroundTasks.ts / background.worker.ts：后台请求、任务通道、取消与硬超时。
- recompute.ts / functionExecutor.ts：批量绑定计算与函数页后台执行。
- manualSave.ts：导出投影和直接对象差异比较。
- lib.rs：JSON checkpoint、迁移备份、导出隔离与显式文件读取。

测试覆盖 JSON 启动零 Markdown 读取、完整身份/状态恢复、导出不覆盖存档、目标文件限定、大文档局部差异、生成成员位置/身份、渐进导入取消与未改变子树引用。运行耗时和真实交互证据放在日志，不作所有设备的性能保证。
