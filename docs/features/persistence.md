# 草稿、保存与刷新

文件格式见 [Markdown](../data/markdown.md) 与 [JSON 存储](../data/json-storage.md)。界面按钮与差异展示见 [文件操作 UI](../ui/pages.md#创作文件操作)。

## 手动读写边界与版本基线

界面中的增删查改、重命名、函数追加、插件、模型和设置操作先修改内存 JSON 对象；属性配置采用下文的独立自动 JSON 保存规则；实时 Markdown 预览是内存对象的序列化结果，并非磁盘文件被实时写入。切页、失焦、定时器和脚本提交不触发持久化。

启动和显式刷新是磁盘读取入口。刷新时正文覆盖 JSON 中对应文件的内容；其他文件草稿保留。保存当前文件和保存全部是写入入口：只序列化提交时的对象快照，不重新读取、解析或合并 Markdown，不按外部修改重试。Rust 直接原子写入提交内容，不读取正文进行 expected 比较。外部修改要先刷新才会进入内存；未刷新直接保存时，当前提交覆盖目标文件的磁盘版本，这是明确的操作语义。

上次成功加载、刷新或保存的对象快照作为版本基线。文件未保存标记比较当前对象序列化后的正文及该文件的配置；实例标记比较实例正文、顺序与标签。执行记录、运行时间或纯内部身份变化不单独造成正文未保存标记。内容改回基线后标记消失，因此不用文件时间戳推断版本先后。没有刷新时，程序不会侦测外部正文改动。

读写共用串行队列，排队保存按提交顺序写各自快照。applySyncResult 仅协调异步完成期间新产生的界面编辑，保留较新输入，不承担磁盘三方合并。失败保留草稿及旧成功基线，不宣称保存成功。

## 属性配置独立持久化

Schema、函数绑定声明与标签定义变更立即进入 JSON 保存队列，无需手动保存。提交仅包含目标类的结构/标签定义、必要组织注册及已保存正文快照；JSON-only 路径只写 .schema.json、world-index.json 与 workspace.json，不读取、验证或写出 Markdown，不改其他文件的正文草稿，也不写脚本文件。未保存正文仍有脏标记，属性配置页不复用正文的保存/刷新按钮及脏标记。

正文刷新读取已独立保存的 Schema，然后按其解析 Markdown；队列确保先完成此前配置写入。用户可以先在磁盘正文新增项，再在属性配置声明该项，最后刷新正文，既不覆盖外部文本，也不恢复旧 Schema。启动仍读取持久化配置和正文；未知正文项依然忽略，不能反向创建结构。

配置写入失败保留内存编辑并提示错误；Ctrl+S 在属性页仅重试 JSON 配置保存，Ctrl+R 不触发正文读取或函数计算。其他页面维持手动保存。当前文件/配置的排队保存保留已经独立提交的最新属性配置，避免早先捕获的投影回滚新声明。

## 操作与提交范围

对象编辑实时生成源码并按字段位置定位；源码编辑使用短防抖解析（约 350ms），成功后更新同一文档对象。无效草稿继续显示错误，保留最后有效对象，明确保存时阻止错误内容落盘。

源码列的开关、高亮和页面恢复由 [文件 UI](../ui/pages.md#markdown-双栏) 负责。创作内容只更新内存草稿，不定时写入、不在切页或焦点恢复时重新加载。保存当前文件（Ctrl+S）先立即解析未完成的源码草稿，提交当前类的 Markdown、Schema 和 JSON 样式/执行状态；其他创作文件使用已保存快照，不夹带其他草稿；桌面写入输出只包含目标正文/结构或视图配置及必要组织清单，不重新写其他正文、Schema 或视图文件。非创作配置保存不导出世界文件。保存全部提交全部当前草稿。新世界首次保存会建立世界初始文件与组织清单；已存在世界的集合保存更新组织清单，现有其他文档正文仍使用已保存基线。

刷新（Ctrl+R）以磁盘文件及 Schema 替换当前文件草稿，取消未完成的源码解析；其他文件的草稿保留。刷新后计算当前文件全部绑定函数，结果仍在内存等待保存。未保存过的文件先保存再刷新。浏览器刷新读 localStorage 的已保存快照；桌面刷新按注册文件名读取，不发现未知文件。插件、模型和设置同样只修改内存 JSON，保存配置时使用已保存世界，不夹带创作修改；Ctrl+S 保存配置，Ctrl+R 读取配置 JSON 和脚本，不读取世界正文。异步保存返回使用 applySyncResult，合并等待期间界面继续编辑的内容。

## 启动、刷新与读取失败

loadWorkspace 先读取/规范化工作区，再读取已注册 Markdown、Schema 和视图配置。启动时无效外部文件明确报错，不静默回退到旧 JSON 实例值，不覆盖原文件。

Schema、Markdown 与已注册视图 JSON 只在加载与显式刷新阶段读取。不进行周期或焦点恢复刷新，不实时发现未知 .md，也不凭正文推断 Schema。这是当前边界，不能把“监测 Markdown”扩写为完整目录同步。

## 导入与脚本

导入解析所选 Markdown 并修改当前内存文档，保持身份和已声明结构；保存后才写入目标正文。未知属性及子树忽略，不从正文生成 Schema。有效导入也可通过明确保存替换损坏的旧文件，无需保存前读取旧文件。

ScriptHost 的 autoSave:false 禁止脚本成功提交和 app.storage.save() 请求隐式写盘。Function、Tool、Agent 生成修改经结构校验进入主程序内存；用户保存时统一落盘。刷新后函数重算结果仍留在内存。

同一世界文件继续平铺在 world 目录，JSON 管理逻辑组织；模型、主题、插件和 Agent 配置共用 workspace.json，保存配置会提交当前非创作配置快照。保存创作当前文件使用已保存的非创作配置，不夹带配置草稿；保存全部统一提交所有当前对象。图片生成等外部工具产物的输出不属于正文保存流程。

## 代码入口与验收

storage.ts：loadWorkspace、reloadCreationFile、refreshWorkspace、reloadPreferences、saveWorkspace 和 applySyncResult；manualSave.ts：提交投影与内容差异标记；AppRoot：手动操作及快捷键；lib.rs：显式读写与原子写入。

验收包括加载和刷新正文优先、保存零正文读取、损坏文件在刷新时报错而明确保存可替换、队列按提交顺序写入、配置保存不读写世界正文、单文件范围隔离，以及函数生成内容只随明确保存写入。

## 桌面写入的实际边界

Rust 的 `write_atomic` 对单个文件使用临时文件再重命名；一次保存会依次写世界文件、函数脚本和 workspace.json，整个文件集合没有跨文件事务回滚。中途失败可能留下部分已写文件，界面仍保留草稿与旧成功基线。这里的“原子写入”指单文件，不表示保存全部可在磁盘整体回滚。保存期间读取旧 workspace.json 只用于清理旧函数脚本，不是保存前读取或合并 Markdown。
