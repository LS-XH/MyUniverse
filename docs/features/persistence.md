# JSON 存档与 Markdown 导入导出

<a id="手动读写边界与版本基线"></a>

## 唯一数据源

所有世界对象、Schema、引用身份、函数来源与执行状态、视图、模型、工具、聊天和 Agent 记忆统一在内存 Workspace 中操作，并自动存档至 workspace.json。JSON 的解码、结构检查和规范化在后台执行，错误存档不进入自动写入；JSON 是上述对象的恢复来源；世界 Markdown、schema.json、view.json 和函数脚本文件均为显式导出产物，启动不以它们覆盖 JSON。

旧 workspace.json 直接兼容规范化。首次写入 archiveVersion=2 时，桌面保留原 workspace.json 为 workspace.before-json-primary.json；备份只建立一次，不修改既有 Markdown，不移动 user 目录。

## 自动 JSON 存档

useWorkspaceArchive 合并连续编辑，首个待写修改约 250ms 后启动一次写入；持续输入不会无限推迟存档。正在写入时记录最新修订，完成后按间隔继续调度，避免追赶流式消息时无限占用写入队列。导出只等待发起时请求的修订，随后新编辑继续独立存档。后台线程负责 JSON.stringify，桌面 checkpoint_workspace 使用 spawn_blocking 校验并单文件原子写入完整 JSON。自动存档不解析、不读取、不写出世界 Markdown，不导出 Function 脚本或视图文件。Skill 包是独立权威文件：保存队列另将变更写入 user/skills，再从 JSON 剥离内存目录；未变化的包不重写，外部版本冲突拒绝覆盖，见 [Skill](skills.md)。限定世界文件导出不修改 Skill 包。

状态显示 JSON 存档中、已存档或失败；失败保留内存内容并支持重试。尚未完成或失败的存档在退出前提示。导出前等待 JSON 存档完成，不以导出投影覆盖完整存档。浏览器模式使用原有 localStorage，JSON 序列化在后台，但浏览器存储 API 本身仍同步。

## 保存按钮：导出

保留保存当前文件和保存全部入口及 Ctrl+S 操作习惯，语义变为明确导出。当前文件只导出目标 Markdown/配置及必要组织清单，不序列化或验证无关类的正文；保存全部导出全部类、视图、聊天及函数脚本。配置页面可导出其对应 JSON。

exportFiles 支持限定类 ID；后台生成并校验导出内容，桌面 export_workspace 在阻塞线程池写出。导出命令不改 workspace.json，不能用旧的单文件投影覆盖其他类已自动存档的数据。

文件与实例的发光标记表示本会话中相较初始或最近导出快照的差异；它们不是 JSON 未存档指示。比较使用对象字段，不在 React 渲染阶段生成全文 Markdown。存档状态单独展示。

## 文件操作按钮

对象页从左到右为：打开文件夹、重新计算函数、填入 MD、导入 MD、刷新、保存、保存全部。对象操作页不显示“新建界面”；集合与导航中的视图创建入口保留。

| 按钮 | 输入与行为 | 函数来源 |
| --- | --- | --- |
| 保存 / Ctrl+S | 当前 JSON 转为对应 MD 并写入磁盘 | MD 不包含来源标记，JSON 保留 |
| 刷新 / Ctrl+R | 读取当前对应 MD，按现有属性配置替换 JSON 并更新界面 | 依据原 JSON 的成员匹配保留函数生成标识；不计算函数 |
| 导入 MD | 选择 MD，按配置替换目标类内容 | 导入内容全部作为普通值 |
| 填入 MD | 选择 MD，只增加新实例或允许重复的新成员，不覆盖旧值、不删除旧分支；相同内容不重复添加 | 新增内容全部作为普通值，既有内容保持原样 |
| 重新计算函数 | 依据当前 JSON 重算当前文档、视图源类或项目中的绑定函数 | 计算结果带函数来源，不读取 MD |
| 保存全部 | 完整 JSON 导出所有对应文件 | 同保存 |

刷新与导入采用替换语义：删除文件缺失的实例和重复成员，固定属性缺失时恢复为空值，顺序跟随文件。填入使用追加语义：已有固定值保留，既有 Object 仅递归增加新子项，新增重复值追加于末尾。两者都不反推或覆盖属性配置，均不执行函数。刷新只信任原 JSON 中的来源，不信任 MD 注释建立来源。

解析在后台完成并校验整个目标文档，校验成功后仅合并当前实例，实例之间让出主线程；导入不占用整个 JSON 写入队列，已完成实例可在导入继续时存档。先显示已完成实例；导入最后删除缺失实例并应用文件顺序，填入保留旧实例与旧值并追加新内容；不提交半个解析对象。整文件初始校验失败不改对象。

导入期间的编辑按稳定 ID 三方合并，独立成员修改保留，重叠修改报冲突而不覆盖。停止导入保留已完成实例和未完成旧内容。全世界导入不是跨文档事务：已完成的文档/实例不因后续失败或取消撤销，均进入自动 JSON 存档。

读取 MD 与函数计算是独立操作。计算支持取消并保留已完成结果；读取失败不会触发函数执行。

## 后台函数与任务边界

JS/Flow 与用户 JS Tool 的计算、JSON 序列化、Markdown 解析、预览与差异生成使用独立 Worker 通道。函数先读取任务快照，在 Worker 中执行世界门面与校验，再仅提交目标实例，使用三方合并保留计算期间的编辑。单次函数调用失败保留旧有效生成值并记录错误，已完成的其他实例不回滚。Python 使用桌面子进程桥。

函数首次扫描限定世界/类，后续只重新定位当前绑定；不在每个任务前扫描完整工作区。普通状态更新不再递归协调全部函数来源，仅协调变化实例，绑定声明或函数集合改变时完整校验。传输后的实例恢复未变化子树的引用，未变化卡片由 memo 跳过渲染。

计算进度按已完成任务推进；停止通过 AbortSignal 终止 Worker 等待及同步死循环，保留已完成实例。单次 JS/Flow 后台执行最多 10 秒，异步脚本自身仍有 5 秒等待上限。Python 的主进程调用不能即时杀掉已开始的子进程，取消后拒绝提交晚到结果；外部网络副作用不属于对象回滚。

## Markdown 预览

右侧 Markdown 以实际磁盘文件原文作为基线，与当前 JSON 生成的待导出内容比较：红色为磁盘中将被删除的行，绿色为 JSON 待写入的新行。打开时立即读取，之后每秒检查并在窗口重新获得焦点时检查；外部修改只更新差异，不导入 JSON。文件不存在时明确提示，全部 JSON 内容显示为新增；读取失败保留上次基线并报错。保存导出后读取新文件，差异随之消失。浏览器没有磁盘路径，仅比较本会话导出的文本。关闭预览停止读取与全文生成，打开后后台生成位置索引、标题层级和差异行，短时合并连续结果更新。大文件采用共同前后缀、Patience 唯一行锚点和有界 LCS；无锚点时用线性空间单调匹配，保留公共行而不按整个大区块删除再新增。

DOM 按每帧最多 200 行 / 8ms 分批协调，按行文本与出现次数复用节点，更新局部行及样式，不因行数变化 replaceChildren 整个编辑区。删除行是只读比较，不写入导出正文。

## 代码入口与验证

- storage.ts：唯一 JSON 加载、自动存档、限定导出、显式导入与渐进发布。
- useWorkspaceArchive.ts：合并写入、重试、退出状态。
- background.ts / backgroundTasks.ts / background.worker.ts：后台请求、任务通道、取消与硬超时。
- recompute.ts / functionExecutor.ts：批量绑定计算与函数页后台执行。
- manualSave.ts：导出投影和直接对象差异比较。
- lib.rs：JSON checkpoint、迁移备份、导出隔离与显式文件读取。

测试覆盖 JSON 启动零 Markdown 读取、完整身份/状态恢复、导出不覆盖存档、目标文件限定、大文档局部差异、生成成员位置/身份、渐进导入取消与未改变子树引用。运行耗时和真实交互证据放在日志，不作所有设备的性能保证。
