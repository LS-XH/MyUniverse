# 世界与文件修改提议、采纳与回退

官方工具先生成提议，用户决定是否改变世界；完整参数见 [官方工具](official-tools.md#世界与交互调用契约)，数据快照见 [聊天数据](../data/chat.md)，差异呈现见 [聊天 UI](../ui/chat.md#实例修改与新增提议)。

## 修改建议与用户采纳

### 输入与生成

propose_instance_change 与 propose_instance_add 均使用三个参数：className、instanceName、markdown（修改后或新实例的完整 Markdown）。没有“修改说明”参数；内部展示说明不改变公开 Schema。

markdown 应采用 get_instance_markdown 返回对象的 markdown 实例格式，以 `## 实例名字` 开始，保留实例名与属性结构。复用原解析器，禁止类一级标题、同时改变其他实例、改名或改 Schema。验证后记录修改前后内容与 Schema 签名，发 onInstanceProposal 事件，不改变实例。

### 原会话定位

聊天处理器在调用 worldId/conversationId 追加建议卡片。切换世界或会话不改变建议归属；明确调用会话已删除时失败，不插入新会话冒充原会话。工具页测试进入调用世界当前聊天，没有会话则创建“实例修改建议”。处理器未就绪时明确失败。

建议及状态属于聊天数据，自动 JSON 存档后可在重启时恢复，状态为 pending/saved/rejected。工具产生建议即发过程事件，工作流继续执行，用户随后决定；按 proposal 稳定 ID 统一查找新旧存储，每份只展示一次。pending 表示等待用户，不得向模型或用户宣称世界已经修改。默认折叠、行差异、状态摘要与长文本排版由 [聊天 UI](../ui/chat.md#实例修改与新增提议) 维护，快照字段由 [聊天数据](../data/chat.md) 维护。

### 新增实例、批量确认与回退

应用自带模板 propose_instance_add（提议添加新实例及其内容）调用名 universe_propose_instance_add，参数 className、instanceName、markdown。提交只校验现有类结构与名称并生成 kind=add 提议，不创建实例；用户采纳后创建稳定 ID 实例。同名实例或类结构变化拒绝保存。新实例差异全部显示为增加行。

上下相邻、同一世界/类身份且 className 相同的新增/修改提议合并为默认折叠组，显示数量与总增删行数，全部保存/全部拒绝只处理 pending 项。正文、思考、其他工具和子调用分隔组，提议工具的成功结果与提议卡片合并避免重复占位。批量处理在不可变临时状态中计算，任一失败不提交整批。

保存记录 savedBefore/savedAfter/savedAt，已保存项提供回退保存，组可回退已保存项（按保存顺序倒序）。修改回退反向合并本次改变的成员内容，保留无冲突后续编辑；新增回退仅在实例内容仍等于保存快照时移除实例。冲突拒绝且保留 saved 状态。成功回退转 pending，可再次采纳。旧 saved 记录没有快照时不提供回退。

### 采纳与过期检查

保存时复查世界、类、实例存在及 Schema 签名。将 before/after 解析为实例，按稳定成员身份比较，只合并建议实际改变的成员内容；未改变的成员保留当前值。成员文本变化通过去掉共同前后缀得到替换内容，在该成员当前文本内唯一匹配后替换；插入需匹配原有上下文。不同成员及可唯一定位的独立文本修改可依次采纳，不因整实例基线不同而全部过期。目标内容找不到、出现多处匹配、目标成员被删或发生重叠冲突时明确指出成员位置并拒绝整份建议，不部分写入。类 Schema 改变仍要求重新生成；合并后再次解析校验，并保留稳定 ID。

拒绝只改建议状态。已保存/拒绝不可重复处理。采纳更新工作区 JSON 对象并自动存档；“已保存”表示已采纳，Markdown 仅在保存当前文件或保存全部时导出，JSON 写入失败由存档状态提示。后续模型请求包含建议处理状态，建议事件不是完成写入的工具结果。

## Runtime 文件提议

runtime_write_file / runtime_edit_file 只在原世界、会话明确的聊天上下文中提交 fileChange 提议，沿用 onInstanceProposal、差异卡片、默认折叠、增删计数、批量确认及回退。提交先校验文件内容和完整包，不更新技能或磁盘；结果为 pending，工作流继续，依赖新文件的后续操作需等用户保存。放弃仅改变状态。

采纳时复查稳定技能身份、名称及目标文件原文：同文件发生变化或同名包被替换时拒绝；其他文件的无关改动保留。用当前包重新构造并检查元数据与 Tool Schema。新包保留提议分配的稳定 ID。保存后记录完整包前后快照；回退要求当前包仍等于保存快照，避免覆盖后续维护；新包回退移除本次创建的包。批量回退按单调保存顺序倒序。提议与快照可随聊天 JSON 恢复，但 Skill 数据源仍为独立目录。

确认动作异步等待 checkpointWorkspace 写入包和 JSON，失败在卡片显示错误，按钮执行中禁用，不能把 pending 当作写入成功。外部磁盘修订冲突由 skillStorage 继续检查。未确认的提议即使根 Agent 结束也不会落盘。

## 事务范围

单份或批量提议在不可变临时状态中验证，冲突不部分提交。用户 JS Tool 的门面写入有独立事务，标记为 write 或 readOnlyHint=false 的自定义 JS/HTTP Tool 先在聊天中请求“保存并执行 / 放弃”，确认前不执行网络或脚本；无法预演的外部接口显示参数确认而非伪造文件差异。普通 action 工具沿用原事务，应用不会根据工具名称猜测未声明的外部副作用。采纳状态、JSON 存档状态和 Markdown 导出状态分别反馈。实现入口为 [instanceProposals.ts](../../src/services/instanceProposals.ts)、[proposalMerge.ts](../../src/model/proposalMerge.ts)、[AppRoot.tsx](../../src/ui/AppRoot.tsx)。
